# Obsidian Worldbuilding Template — Design

**Date:** 2026-09-25
**Repo:** https://github.com/Crits4Kids/obsidian-worldbuilding-template
**Status:** Approved in brainstorming; awaiting written-spec review.

## 1. Goal

A Git-hosted Obsidian vault template for running any TTRPG. The workflow: mark the repo as a GitHub template → "Use this template" per game → clone → open the folder in Obsidian → click "Trust author and enable plugins" → ready to go.

### Requirements (from the user)

1. Mimic as much of the standalone app **Chronicler** as practical.
2. Game-system agnostic.
3. Git-based, using **Obsidian Git**.
4. Plugins: Templater, Dataview, QuickAdd, Calendarium, Leaflet, Excalidraw, a family-tree plugin (**Charted Roots**), Find Orphaned Files and Broken Links, Tag Wrangler, Minimal theme + Style Settings, Obsidian Git.
5. Compatible with the Foundry VTT module **Obsidian Bridge** (SoSly/foundryvtt-obsidian-bridge).
6. Easy translation of **Deck of Worlds** card stacks into linked pages.
7. A **World Bible** note that the Obsidian MCP reads first, to keep token usage low.
8. Clone-and-go: no manual plugin installation.

### Decisions made during brainstorming

| # | Question | Decision |
|---|---|---|
| Q1 | Starting point | Combine: Chronicler-style families from `~/Obsidian/Worldbuilding Vault` + campaign-running pieces (Campaign Bible, clocks, sessions, archive, load-context idea) from `~/Obsidian/TTRPG-Template` |
| Q2 | Chronicler compatibility | Hybrid: Chronicler frontmatter keys (`title`, `subtitle`, `infobox`, `image`, `layout`); Obsidian syntax for spoilers (callouts) and inserts (`![[embeds]]`) |
| Q3 | Vault scope | One world per clone, campaign-first by default, supports multiple campaigns via `Campaigns/<Name>/` |
| Q4 | Deck of Worlds input | Guided QuickAdd entry, card by card; no card text shipped (copyright) |
| Q5 | World Bible | Hybrid: hand-written top + generated index between markers |
| Q6 | MCP | `@bitbonsai/mcpvault` (filesystem); no Local REST API plugin or keys in the template |
| Q7 | Family tree | Charted Roots |
| Q8 | Plugin delivery | Commit plugin code + theme + settings; `update-plugins.sh` refreshes them |
| Q9 | GM secrets vs Foundry | `[!gm]` callouts inline; "Export player handouts" command copies shareable notes to `Player Handouts/` with secrets stripped; Foundry shares only that folder |
| Q10 | Git per game | GitHub template repo + `sync-template.sh` that updates only template-owned paths |
| — | Infobox rendering | Static `[!infobox]` callout generated from frontmatter by Templater/QuickAdd ("Refresh infobox"); no live code in content notes |

### Guiding constraint: content notes are plain Markdown

Obsidian Bridge and the MCP read note bodies as raw text. **Content notes (everything outside `_System/` and `Home.md`) must never contain Dataview, DataviewJS, Templater, or other plugin code.** Dynamic views live only in `Home.md` and `_System/Dashboards/`.

## 2. Vault layout

```
/
├── Home.md                  Dashboard (Dataview; Obsidian-only)
├── World Bible.md           Hand-written top + generated index (MCP entry point)
├── CLAUDE.md                AI instructions: read World Bible first; schema pointer
├── README.md                Setup and usage
├── LICENSE                  (existing)
├── World/
│   ├── People/              type: person   person_type: pc | npc | enemy | monster
│   ├── Groups/              type: group    group_type: power | guild | faith
│   ├── Places/              type: place    place_type: region | settlement | building | landmark
│   ├── Things/              type: thing    thing_type: magic_item | key_item | mundane_item
│   ├── Lore/                type: lore     lore_type: deity | species | plane | history | culture
│   └── Plot/                type: plot     plot_type: hook | event | fact | clock
├── Campaigns/
│   └── Example Campaign/
│       ├── Example Campaign.md   type: campaign
│       ├── Arcs/                 type: arc
│       └── Sessions/             type: session (GM notes) / type: recap (player recaps)
├── Micro-settings/          type: microsetting (Deck of Worlds stacks)
├── Maps/                    Leaflet map notes; map images in Assets/Maps/
├── GM Toolkit/              House Rules, Run Sheet, rumor tables, encounters
├── Player Handouts/         GENERATED by "Export player handouts"; do not edit by hand
├── Assets/                  Images, Maps/, Tokens/, Excalidraw/
├── Archive/                 Mirrors family folders; status: archived
├── docs/                    Specs/plans (excluded from Obsidian search via userIgnoreFilters)
└── _System/                 Template-owned
    ├── Templates/           Templater templates
    ├── Scripts/             Templater user scripts + QuickAdd macro JS
    ├── Bases/               .base files (per-family tables)
    ├── Dashboards/          Dataview dashboards incl. Maintenance
    ├── Schema.md            Frontmatter schema reference (human + AI)
    └── tools/               update-plugins.sh, sync-template.sh, validate.mjs
```

- Maximum folder depth under any Foundry-imported root: 3 (`Campaigns/<X>/Sessions`), within Foundry's folder-depth limit.
- Foundry (Obsidian Bridge) imports: `World/`, `Campaigns/`, `Maps/`, `Micro-settings/` as GM-only; `Player Handouts/` as the player-shared import. `_System/`, `Assets/` (except as linked), `docs/`, and `Archive/` are not imported.
- Timeline events are `World/Plot` notes with `plot_type: event` and a Calendarium `fc-date`. There is no separate Timeline folder.
- Clocks (from TTRPG-Template) are `plot_type: clock` with `stage`, `max_stage`, `owner` (link to a Group or Person), and `trigger`.

### Template-owned paths (overwritten by `sync-template.sh`)

`_System/`, `.obsidian/plugins/`, `.obsidian/snippets/`, `.obsidian/themes/`, `CLAUDE.md`, `docs/`. Everything else is world content and is never touched by sync.

## 3. Note schema

### Common frontmatter (all content notes)

```yaml
title: Rivertown                    # Chronicler display title; equals filename
subtitle: Free city of the Sorn delta
infobox: City-state                 # Chronicler header shown under the image
image: "[[Assets/rivertown.jpg]]"   # string, or list for a carousel
type: place
place_type: settlement              # per-family subtype key: <type>_type
status: active                      # active | background | archived
campaigns: ["[[Example Campaign]]"] # empty = world-level
summary: One-line description.      # REQUIRED; feeds the World Bible index
share: false                        # true = included in "Export player handouts"
aliases: []
tags: [place]
layout: []                          # optional Chronicler infobox layout rules
```

### Per-type infobox fields

| Type | Fields |
|---|---|
| person | `role`, `species`, `faction` (links), `location` (link), `father`, `mother`, `spouse`, `children` (links; Charted Roots keys), `born`, `died` (Calendarium date strings), `pronouns` |
| group | `group_type`, `leader`, `headquarters`, `goal`, `allies`, `rivals` |
| place | `region`, `ruler`, `population`, `map` (link to map note), `location` (Leaflet coords, optional) |
| thing | `owner`, `location`, `rarity` (free text) |
| lore | `domain`, `related` |
| plot | `fc-date` (event), `stage`/`max_stage`/`owner`/`trigger` (clock), `resolved` (hook) |
| campaign | `system` (free text), `players`, `start`, `status` |
| arc | `campaign`, `order`, `status` |
| session | `campaign`, `arc`, `session_number`, `date` (real-world), `fc-date` (in-world), `players_present` |
| microsetting | `region_card`, `cards` (list of links in stack order) |

Charted Roots may add its own ID properties (e.g., `cr_id`); these are allowed and ignored by the infobox.

No system-specific stat fields. Each person/thing note has a free-form `## Stats` section.

### Body structure

```markdown
> [!infobox]+ Rivertown
> ![[rivertown.jpg]]
> | | |
> |---|---|
> | **Region** | [[Sorn Delta]] |
> | **Ruler** | [[Mira Vell]] |

Player-facing description…

> [!gm]- GM only
> Secrets, true motives, unrevealed facts.

## Connections
- [[...]]
```

- The infobox callout is generated by the "Refresh infobox" command and is regenerated from frontmatter. Users do not hand-edit it. The callout's first line is the only marker needed: the command replaces the contiguous `> ` block that starts with `> [!infobox]`.
- Chronicler `layout` rules supported by the renderer: `header` (text, below), `separator` (above), `alias` (keys → label), `group` (keys rendered on one row).
- `image` lists render as a `[!gallery]` carousel inside the infobox (CSS-driven).
- Callout types (styled by CSS snippets):
  - `[!infobox]`: wiki infobox, floated right on wide panes.
  - `[!gm]`: GM secret; stripped on handout export.
  - `[!spoiler]`: collapsed, reveal-able player content (Chronicler `||spoiler||` analogue); kept on export.
  - `[!gallery]`: image grid/carousel.

## 4. Templates (`_System/Templates/`)

Person, Group, Place, Thing, Lore, Plot Hook, Event, Clock, Campaign, Arc, Session, Player Recap, Micro-setting, Map, Encounter, Rumor Table, World Seed.

- Each template prompts for a name and subtype and renames the file. It writes the frontmatter, calls the shared infobox renderer (`_System/Scripts/infobox.js`), and inserts the standard body sections.
- Templater folder templates map each `World/<Family>/` folder, `Campaigns/`, `Micro-settings/`, and `Maps/` to its template, so a new note created in those folders gets the right template automatically.
- Content carried over from source vaults: the World Seed questions and the "Snippets" prompts (Worldbuilding Vault); the Campaign Bible sections, clock stages table, session "Decisions that matter later"/"Loose threads", run sheet, rumor table, and encounter templates (TTRPG-Template).

## 5. Automations (QuickAdd → `_System/Scripts/*.js`)

| Command | Behavior |
|---|---|
| **New entity…** | Prompt family → subtype → name; create the note in the correct folder via template. |
| **New campaign** | Create `Campaigns/<Name>/` with the campaign note, `Arcs/`, and `Sessions/`; set it as the active campaign (`_System/settings.json` or a frontmatter flag `active: true`). |
| **New session** | Next `session_number` in the active campaign; link the previous session; copy its "Loose threads" into "Threads carried forward". |
| **Refresh infobox** | Rebuild `[!infobox]` from frontmatter + `layout`. Scope: current note, current folder, or whole vault. |
| **Rebuild World Bible** | Replace the content between `<!-- WB:INDEX START -->` and `<!-- WB:INDEX END -->` (format below). |
| **Deck of Worlds: new micro-setting** | Guided card entry (Section 6). |
| **Export player handouts** | For notes with `share: true`: copy to `Player Handouts/<Family>/`; remove `[!gm]` callouts; convert links to non-shared notes into plain text; drop frontmatter keys except `title`, `subtitle`, `infobox`, `image`, `type`, `tags`. Deletes stale files in `Player Handouts/` that no longer have `share: true`. |
| **Archive note** | Set `status: archived`; move to `Archive/<Family>/`. |

### World Bible format

```markdown
# World Bible
<!-- hand-written -->
## How to use this vault (for AI)   ← fixed pointer to CLAUDE.md / _System/Schema.md
## Premise
## Tone & pillars                   ← World Seed answers
## Current state                    ← active campaign, where the party is, what's in motion
## Open mysteries
<!-- WB:INDEX START -->
_Generated YYYY-MM-DD HH:mm — do not edit below this line._
## People (N)
- [[Mira Vell]] — npc · active · Harbormaster of Rivertown…
## Groups (N) … ## Places (N) … ## Things (N) … ## Lore (N) … ## Plot (N)
## Active clocks
- [[The Drowning]] — 3/6 · owner [[Tide Court]]
## Campaigns
- [[Example Campaign]] — current arc [[Arc 1]] · last session [[Session 3]] — summary
## Micro-settings (N)
## Archived: N notes (not listed)
<!-- WB:INDEX END -->
```

Included: `status` active or background. Grouped by family, sorted by name. Each entity takes one line: `link — subtype · status · summary`. Notes missing `summary` show `(no summary)` and are listed in the Maintenance dashboard.

### CLAUDE.md (vault root)

1. Always read `World Bible.md` first; its index describes every active entity.
2. Open individual notes only when their details are needed.
3. Schema: `_System/Schema.md`. Folder = family; `<type>_type` = subtype.
4. When creating or editing notes: use the matching template's structure, keep `summary` accurate, put secrets in `[!gm]` callouts, never edit inside `[!infobox]` blocks or the World Bible index markers (ask the user to run the refresh commands instead), never put plugin code in content notes.
5. Do not read `_System/`, `.obsidian/`, `Assets/`, `Archive/`, or `Player Handouts/` unless asked.

## 6. Deck of Worlds flow

1. Prompt: micro-setting name; Region card biome (free text or suggester: Coast, Desert, Forest, Mountain, Plains, Swamp, Tundra, Other).
2. For each card slot in order (Landmark → Namesake → Origin → Attribute → Advent), with a "skip" option per slot:
   a. Card text (multiline prompt; the user types or pastes it).
   b. What it becomes: new Place / Person / Group / Lore / Plot event / Plot hook, or link to an existing note (suggester over the vault).
   c. Name (for new notes).
3. Create the new notes from their templates with `summary` pre-filled from the card text. Their `## Connections` section links back to the micro-setting and the adjacent cards.
4. Write `Micro-settings/<Name>.md`: frontmatter `cards:` in stack order; body is an ordered table (Slot | Card text | Became), then an empty "Story in one paragraph" section and a `[!gm]` section.
5. Offer to run "Refresh infobox" and "Rebuild World Bible".

No card text ships with the template.

## 7. Plugins and configuration

All committed under `.obsidian/` with `data.json` settings.

| Plugin / theme | Configuration |
|---|---|
| Templater | Template folder `_System/Templates`; user scripts `_System/Scripts`; folder templates per Section 4; trigger on new file creation. |
| Dataview | JS queries enabled (dashboards only). |
| QuickAdd | Commands from Section 5, registered in the command palette; no hotkeys preset. |
| Calendarium | One editable sample calendar "World Calendar"; parses `fc-date` frontmatter; events folder `World/Plot`. |
| Leaflet | `Maps/World Map.md` with a placeholder image in `Assets/Maps/`; markers from note frontmatter `location`. |
| Excalidraw | Folder `Assets/Excalidraw`. |
| Charted Roots | People folder `World/People`; calendar source Calendarium. |
| Find Orphaned Files and Broken Links | Ignore `_System/`, `Assets/`, `docs/`, `Player Handouts/`. |
| Tag Wrangler | Defaults. |
| Obsidian Git | Auto commit+push every 10 min; pull on startup; commit message `vault backup: {{date}}`. |
| Minimal theme + Style Settings | Minimal active; Style Settings defaults committed. |
| CSS snippets | `chronicle.css` (wiki headings/typography), `infobox.css`, `callouts.css` (gm/spoiler), `gallery.css`; all enabled. |

Core plugins enabled: Bases, Canvas, Backlinks, Outgoing links, Properties, Graph (colour groups per family tag), Templates **disabled** (Templater replaces it).

`app.json`: new-note location `World/`; attachments folder `Assets/`; `userIgnoreFilters: ["docs/"]`; wikilinks on; always update links.

## 8. Git

- `.gitignore`: `.obsidian/workspace*.json`, `.obsidian/cache`, `.obsidian/plugins/*/data-cache*`, `.smart-env/`, `.trash/`, `.DS_Store`.
- `.gitattributes`: images, PDFs, and fonts marked `binary`. No Git LFS.
- The repo is flagged as a GitHub template repository (a manual GitHub settings step, documented in the README; `gh repo edit --template` if the user approves).
- `_System/tools/update-plugins.sh`: for each plugin in a manifest (`_System/tools/plugins.json`: id → GitHub repo), download `main.js`, `manifest.json`, and `styles.css` from the latest release into `.obsidian/plugins/<id>/`. Same for the Minimal theme.
- `_System/tools/sync-template.sh [template-remote-url]`: fetch the template repo and check out only the template-owned paths (Section 2) into the current game repo, then show the diff for review. It never commits automatically.

## 9. Verification

1. `_System/tools/validate.mjs` (Node, no dependencies), run manually and before commits. It checks:
   - every content note has `title`, `type`, `status`, `summary`, and a valid `<type>_type`;
   - `[!infobox]` is present and first in the body;
   - no Dataview/Templater code blocks appear in content notes;
   - World Bible markers are present;
   - folder depth under import roots is ≤ 3.
2. Unit-style tests for the pure JS logic (infobox rendering from frontmatter + layout, World Bible index generation, handout stripping), runnable with `node --test`. Scripts are structured so this logic lives in pure functions separate from the Obsidian API calls.
3. Manual Obsidian smoke test (user): fresh clone → open → trust plugins → run each QuickAdd command → check the dashboards, calendar, map, and family tree.
4. Manual Foundry checklist (user): import `World/` via Obsidian Bridge → callouts and links render; import `Player Handouts/` → no `[!gm]` content present.

## 10. Example content

Minimal example content ships so the dashboards aren't empty: one of each family, one campaign with one arc and one session, and one micro-setting. It's all tagged `example` and uses `status: background`. A README step (and a QuickAdd command, **"Remove example content"**) deletes it.

## 11. Out of scope

- Mobile-specific setup; Smart Connections; Local REST API / MCP Tools.
- Shipping any Deck of Worlds card text or game-system content.
- Automatic Foundry sync (Obsidian Bridge is driven from Foundry).

## 12. Open risks

- **Obsidian Bridge handling of callouts and frontmatter is undocumented.** `[!infobox]`/`[!gm]` may render as plain blockquotes in Foundry. This is acceptable because GM-only journals aren't shared, but it needs checking with the manual Foundry checklist.
- **Charted Roots, Calendarium, and QuickAdd settings formats change between versions.** Committed `data.json` files may need regenerating after `update-plugins.sh`.
- **Plugin licenses:** confirm that each committed plugin's license permits redistribution before the first push. Any that doesn't gets installed by `update-plugins.sh` on first run instead.
